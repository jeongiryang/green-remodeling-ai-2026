# 예선 제안서 집필 틀

실제 집필: `deliverables/proposal.md`. PPT/PDF 최종 파일은 별도로 생성한다. 아래 15쪽은 내부 구성안으로 필요에 따라 합쳐 줄이며 표지·참고자료까지 15쪽 이내로 맞춘다.

| 쪽 | 전달할 내용 | 연결할 평가·증거 |
|---|---|---|
| 1 | 작품명과 누구의 어떤 문제를 푸는지 | 식별정보 제외 |
| 2 | 노후 건물의 현황과 문제 | 원문·통계·관찰, C/S ID |
| 3 | 주요 이용자와 현재 행동·불편 | 사용자 특성, 문제 이해 |
| 4 | 기존 해결 방식과 한계 | 실제 기존 서비스 비교 |
| 5 | 제안 개요와 차별화된 핵심 | 적합성·창의성 |
| 6 | 이용자 흐름 | 입력→결정→행동→확인 |
| 7 | 핵심 화면 1 | 누구나 이해 가능한 예시 |
| 8 | 핵심 화면 2 / 결과·근거 표시 | 오류·불확실성 표현 |
| 9 | AI 처리 구조와 필요성 | 규칙·검색·통계 대비 AI 가치 |
| 10 | 데이터 확보·품질·이용 조건 | 확보/요청/예시 구분 |
| 11 | 그린리모델링 요소와 실제 행동 연결 | 단열·창호·설비·운영 등 |
| 12 | 검증 계획과 기대효과 | 기준선·지표·실측/추정/목표 구분 |
| 13 | 운영·비용·위험·대체 동작 | 실현가능성 |
| 14 | 본선 최소 구현과 확장 계획 | 본선 발전가능성 |
| 15 | 출처와 생성형 AI 활용 명세 | 각주·도구·활용 범위·사람 검토 |

시각자료 명세는 `deliverables/visuals.md`에 화면 이름·입력값·표시 결과·사용자 행동·그림 파일 경로를 기록한다. 예시·목업은 실서비스나 실측 결과처럼 표현하지 않는다. 완성된 시각자료를 실제 제안서에도 1개 이상 포함한다.

주장 C ID는 내부 검증용이다. 최종본에는 검토 가능한 각주·출처 표기로 바꾸고 이름·학교·개인 계정·로고 등 식별정보를 점검한다.
