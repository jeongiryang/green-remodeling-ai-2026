# 본선 진출 후 구현 계획 틀

진출 확인 뒤 `work/implementation-plan.md`에 작성한다.

1. 공식 본선 안내와 변경·추가 요구사항, 결과물 규격·마감.
2. 예선 아이디어에서 유지할 핵심 문제와 목표 사용자.
3. 반드시 작동시킬 이용 흐름 하나, 포함·제외 기능과 완료 조건.
4. 입력 데이터의 출처·권한·실제 확보 상태. 예시 데이터와 실데이터 표시.
5. 기술 구성·실행 환경·비용·팀 역할·현장 작업 순서.
6. AI와 단순 기준선의 비교, 지표·평가 사례·오류/불확실성 처리.
7. 기능 테스트·접근성·보안·개인정보·오프라인 또는 API 장애 대안.
8. 실제 구현한 것과 향후 계획의 구분, 발표·질의응답 준비.

`work/verification.md`에는 실행 명령, 테스트한 코드의 커밋 또는 파일 해시, 데이터 버전, 결과 로그·스크린샷 경로, 실패와 해결, 남은 한계를 기록한다. 제안서의 검증 계획을 실행 결과로 바꾸어 쓴다.

`deliverables/final/demo.md`에는 발표·시연 순서, 준비 데이터, 화면별 행동·예상 결과, 소요시간, 네트워크 장애 시 대안과 예상 질문을 기록한다. 본선 안내가 변경하지 않았다면 발표 10분·질의응답 약 5분을 기준으로 연습한다.

예선 제출 원고·제출 파일은 보존하고 본선 문서와 구현 파일은 별도 경로에 둔다. 실제 테스트 결과·시연을 확인한 뒤 최종 검토를 기록한다.
