# 진행 하네스

이 하네스는 Codex가 조사·기획·문서 작성·검토·본선 구현을 이어가기 위한 작업 절차와 검사 도구다. Python 3.11 이상만 필요하며 API 키·별도 에이전트 서버는 필요하지 않다. AI를 백그라운드로 자동 호출하거나 접수 사이트에 자동 제출하는 프로그램은 아니다.

## 시작·재개

```powershell
python scripts/harness.py status
python scripts/harness.py next
python scripts/harness.py validate
```

`harness/state.json`이 현재 단계의 기준이다. `STATUS.md`는 사람이 읽는 요약이다. 작업자는 현재 단계의 입력을 읽고 산출물을 작성한 뒤 `check`로 빠진 항목을 확인한다. 통과하면 `advance`로 한 단계만 전환한다. 전환 내역은 `harness/history.jsonl`에 남는다. 파일 경로는 저장소 기준 상대 경로를 사용한다.

```powershell
python scripts/harness.py check
python scripts/harness.py advance
```

검사 실패는 하네스 고장과 다르다. 지금은 후보와 제출물이 없으므로 `validate`는 성공하고 `check`는 미완료 항목을 표시하는 것이 정상이다. 통과하려고 가짜 후보·출처·서명·검토 결과를 채우지 않는다.

## 단계별 실행과 완료 기준

| 단계 | 작업·입력 | 산출물·통과 기준 | 미달 시 돌아갈 작업 |
|---|---|---|---|
| ideation | `harness/IDEATION.md`에 따라 문제 공간을 넓힌 뒤 공식·1차 출처, 데이터 접근성, 기존 방식과 AI 필요성을 조사 | 출처 목록, 근거를 역할별로 연결한 후보 최소 3개, 예선 배점 기준 비교와 반대 검토 | 문제·데이터·기존 서비스 조사 |
| decision | 후보의 장점·한계·선택 근거를 사용자에게 제시하고 결정 내용을 기록 | 선정 후보 ID, 결정 기록. 선정을 위임받으면 위임과 판단 근거 기록 | 후보 보강·비교 |
| proposal | 선정 문제·이용 흐름·AI 역할·검증 방안으로 제출 문서 작성 | 제안서·공식 요약서 구조·시각자료·AI 활용기록·주장 목록 | 부족한 근거·서비스 범위 수정 |
| review | 문서 검토 및 실제 PPT/PDF/HWP·신청 서류 제작, 화면으로 열어 확인 | 분량·파일·증빙 검사, 검토 기록, 현재 파일 해시로 검토 확정 | 문서·내보내기·서명 취합 |
| submission | 준비된 자료와 온라인 신청을 대조하고 접수 | 접수 시각·확인 증빙. 준비 완료를 접수 완료로 기록하지 않음 | 접수·수신 확인 |
| results | 제출본 보관. 운영기관 결과 확인 | 본선 진출/미선정 증빙. 진출 시 다음 단계, 미선정 시 종료 | 결과 확인 대기 |
| finalist_plan | 본선 추가 규격을 먼저 읽고 예선 아이디어의 최소 구현 범위 설계 | 공식 본선 안내, 구현 계획, 기능·데이터·평가·일정 | 본선 요건·구현 범위 조정 |
| implementation | 정한 핵심 이용 흐름 구현, 실제 테스트와 실패·대체 동작 검증 | 코드·실행법을 참조한 검증 기록, 재현 가능한 시연 대본 | 결함 수정·데이터 검증 |
| final_review | 본선 규격·사용자 편의성·시연·발표·질의응답 검토 | 본선 제출 파일, 검토 확정, 실제 제출 증빙 | 구현·발표·내보내기 수정 |
| done / closed | 완료 또는 미선정 | 회고와 최종 파일 보관 | 다음 지시 |

`minimum_candidates=3`은 내부 탐색 기준이며 공식 출품 조건이 아니다. 합리적인 사유로 바꾸면 결정 기록에 이유를 남긴다. 비교 점수는 내부 판단 보조이며 수상 확률·예상 심사점수가 아니다.

아이디어 도출·심층 분석은 `harness/IDEATION.md`가 전담한다. 후보마다 문제, 데이터 접근, AI 입력·방법·출력·필요성, 검증, 예선 화면을 분리해 기록한다. `check`는 구조와 출처 ID 연결만 검사하므로 원문이 실제 주장을 뒷받침하는지 사람 검토가 필요하다.

## 지금의 우선순위

1. 후보 탐색과 선택에 필요한 근거 확보.
2. 표지 포함 15쪽 이내 PPT·PDF와 2쪽 요약서, 시각자료 작성.
3. 신청·동의·서약·재학 증빙을 병행 준비하고 접수 확인.

예선에는 화면 시안·흐름도로 제안을 설명할 수 있다. 현재 제품 개발·배포·인프라 구축은 우선하지 않는다. 본선 진출 뒤에 구현한다는 사용자 요청을 따른다. 본선에서도 완제품 출시를 공고 의무로 단정하지 않고 새 안내와 팀 계획에 맞춰 구현한다.

## 역할과 작업 책임

| 역할 | 해야 할 일 | 완료 증거 |
|---|---|---|
| 진행 담당 | 현재 단계·마감·의존 작업·다음 행동 관리 | state, STATUS, 결정 기록 |
| 조사 담당 | 건물·이용자 문제, 기존 서비스, 데이터·출처 확인 | sources, candidates, comparison |
| 서비스·AI 설계 담당 | 입력→AI→출력, 기존 방식 대비 가치, 실패 시 처리 | 후보 카드·제안서·시각자료 |
| 작성 담당 | 제안서·요약서의 이야기와 수치·표현 일치 | deliverables |
| 검토 담당 | 근거·공고·분량·블라인드·파일 열림 검토 | checks의 실증 기록과 검토 확정 |
| 본선 구현 담당 | 핵심 흐름 구현·테스트·시연 | work와 final 산출물 |

이는 작업 책임을 구분한 것이며 상시 병렬 에이전트를 뜻하지 않는다. 기본은 한 Codex 세션이 역할을 순서대로 수행한다. 팀원의 실제 역할은 아직 미정이다. 같은 최종 파일의 작성자는 한 명으로 두고, 검토 중 결함은 작성 단계로 되돌린다.

## 데이터 기록 형식

`harness/DATA.md`의 형식을 따른다. 출처는 읽은 문서·페이지 위치를 기록하고, 사실·추정·목표·가설을 분리한다. 제안서에는 주장 ID(C001 등)를 내부 집필용으로 연결한 뒤 제출 시 읽기 쉬운 각주로 바꾼다.

검토 체크는 `checks/preliminary-review.json` 또는 `checks/final-review.json`에서 항목별 `passed`, 근거 문서 경로를 채운다. 검토자는 실제로 확인한 내용만 통과로 기록한다. 검토 기록을 모두 채운 후 다음 명령으로 현재 원고·근거·제출 파일의 해시를 묶는다.

```powershell
python scripts/harness.py seal-review preliminary --reviewer "검토자 이름 또는 세션"
python scripts/harness.py seal-review final --reviewer "검토자 이름 또는 세션"
python scripts/harness.py hash deliverables/example.pdf
```

검토 후 대상 파일이 바뀌면 기존 검토는 만료된다. 수정 부분을 다시 확인하고 확정한다. 원고·증거 파일은 빈 파일이나 `TODO`, `TBD`, `작성 예정` 같은 빈칸 표시가 남아 있으면 통과하지 않는다.

검사 도구는 문서의 진실성·좋은 아이디어 여부·실제 서명·PDF 시각 품질을 판정하지 못한다. PPTX 슬라이드 수는 자동 계산하고 PDF/HWP 쪽수는 직접 열어 기록한 값과 검토 근거를 사용한다. 최종 판단은 실제 파일과 공고를 읽는 검토자가 맡는다.

## 마감·개인정보·접수

- `status`에서 공식 마감까지 남은 시간을 한국 시간으로 확인한다. 마감이 지나면 접수 가능 여부를 운영기관에서 확인한다. 도구는 접수를 보장하지 않는다.
- 증명서·연락처·서명본·접수 증빙은 Git에서 제외된 `private/`에 둔다. 제출 manifest에는 경로·해시만 기록한다. 다른 팀원 PC와 CI에서 해당 파일이 없는 것은 제출 준비 검사 실패로 나타난다.
- GitHub CI는 하네스 구조와 동작을 검사하며 실제 접수 가능 여부를 인증하지 않는다.
- 외부 제출은 사용자가 현재 세션에서 승인한 범위에 따라 수행한다. 제출을 아직 요청하지 않았다면 최종 파일과 접수 정보를 먼저 완성해 검토 가능하게 한다.
- 불확실한 팀 정보만 기다리며 조사를 멈추지 않는다. 서명·증빙은 해당자가 준비하고 그동안 후보·문서 작업을 진행한다.
