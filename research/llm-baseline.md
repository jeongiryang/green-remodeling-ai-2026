# 범용 LLM 대비 7개 후보 재심사

2026-09-29 · 사용자 요청에 따른 **선정 전 재검토**. 아래 차별성은 제품 성능이 입증된 사실이 아니라 예선 제안에서 검증해야 할 가설이다. 기존 내부 점수는 이 기준을 반영하지 않았으므로 순위 근거로 사용하지 않는다.

## 비교 기준

공정한 기준선은 ChatGPT/Claude에 **우리 서비스와 같은 입력 자료**(견적·사진 설명·설명서·규칙표 등)를 주고, 비교·추출·표 작성까지 요청하는 것이다. 이들 제품은 이미 PDF 업로드, 문서 비교·추출, 프로젝트 지식 사용을 지원한다. 따라서 ‘문서 업로드 + 요약’, ‘질문에 답함’, ‘출처를 붙임’은 단독 차별점이 아니다. LLM에 없는 기능이라고 주장하지 않는다.

별도 서비스의 필요성은 ① 공사 결정의 특정 시점에 필요한 입력·상태를 수집하고 ② 확인된 제품·규칙·기록과 대조하며 ③ 근거 부족·범위 불일치 때 자동으로 판단을 보류하고 ④ 사람이 정정·확인할 결과를 저장하는 **반복 가능한 업무 흐름**에서 증명해야 한다. 이 기능도 범용 LLM에 도구와 지침을 붙이면 재현할 수 있으므로, 독점 기술이 아니라 사용자에게 필요한 절차의 제품화다. 같은 자료로 일반 LLM과 비교한 시험은 아직 하지 않았다.

기준선 출처: [OpenAI 파일 업로드—문서 비교·추출](https://help.openai.com/en/articles/8982896-how-does-the-new-file-uploads-capability-work), [OpenAI 데이터 분석—PDF와 표 분석](https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt), [Anthropic Claude 프로젝트 지식](https://support.anthropic.com/en/articles/9517075-what-are-projects), [Anthropic 지원 문서 형식](https://support.anthropic.com/en/articles/8241126-what-kinds-of-documents-can-i-upload-to-claude-ai). 2026-09-29 확인.

## 후보별 판정

|---|---|---|---|
| I001 그린견적 | 견적 2개에서 항목을 뽑아 표로 비교하고 질문 작성 | 창호 모델·구성의 **정확 일치**를 공개 성능 근거와 대조, 공사 범위·단위 검증, 원문 위치·사용자 정정, 불일치 시 비교 보류를 일관되게 수행 | **우선 심화.** 실견적 부재·기존 견적 AI와의 중첩은 남는다. ‘AI 비교표’만 구현하면 탈락 |
| I007 그린증빙 | 사진·설명을 받아 체크리스트와 빠진 항목 제안 | 작업 범위·공간·시점에 따라 **가려지기 전** 필요한 기록을 수집하고 제출/검토/누락 상태를 지속 관리 | **조건부 대안.** 기존 현장 기록 앱과 다른 점, 시공 담당자의 사용 의사와 검수 항목을 확인해야 함 |
| I006 그린순서 | 희망 공사·예산을 주면 단계별 순서안 작성 | 전문가 검수된 소수 선행 조건을 규칙으로 대조하고 충돌·미확인 사항에서 판단 보류 | **연구 보류.** 국내 공법·규칙 검수자가 없으면 LLM의 일반적인 순서 제안과 차이 약함 |
| I003 그린문진 | 거주자에게 추가 질문하고 상담 요청서 작성 | 정해진 필드·누락 상태·현장 확인 항목 저장은 가능 | **이번 선별에서 후순위.** 기본 흐름이 LLM 대화와 매우 유사하며 실제 상담 창구도 미확인. 기존의 ‘쉬운 구현 대안’ 추천은 철회 |
| I002 그린인수인계 | 설명서 PDF를 읽고 모델별 사용·관리 요약 | 여러 담당자의 확인·미해결 문의를 누적 인계 | **후순위.** 인계 상태 관리의 실수요·자료 없이 문서 챗봇과 구별 약함 |
| I004 그린합의 | 양측 조건을 표로 정리하고 충돌·대안 설명 | 양측 확인 상태·규칙 계산·이력 관리 | **후순위.** 핵심 병목이 자금·신뢰라면 표·대화 개선만으로 해결 불가 |
| I005 그린체크백 | 사용량 표·기온 자료를 올려 분석·그래프·해석 | 검증된 통계 절차와 데이터 충분성 검사를 반복 실행 | **이번 접수에서는 보류.** 실제 전후 데이터·통계 검수 부족, 유사 분석법·선행작 중첩 |

이는 기존 7개 후보를 삭제하거나 최종 주제를 선정한 것이 아니다. **제출 문서에 집중할 후보는 I001**, 견적 자료·차별성 입증이 막히면 **I007을 조건부 대안**으로 검토한다. I006은 기술 검수자가 확보될 때만 다시 올린다. 두 선두 후보 모두 구현 담당·API·가용시간과 자료 검수 조건이 아직 확인되지 않아 `conditional`이다.

## 심사 질문에 대한 답변 틀 — I001

**“ChatGPT에 견적서 두 장을 올려 비교해 달라고 하면 되지 않나요?”**

“기본 표 비교는 가능합니다. 그래서 우리 아이디어의 핵심은 챗봇이 견적을 요약하는 기능이 아닙니다. 창호 견적의 제품 모델·구성과 철거·폐기·마감 범위를 같은 기준으로 확인하고, 공개 성능 자료에 **정확히 대응되는 항목만** 연결합니다. 모델이 비슷하지만 일치하지 않거나 공사 범위가 빠졌다면 더 싼 쪽을 추천하는 대신 ‘비교 불가’와 확인 질문을 보여줍니다. 사용자가 원문을 보며 추출값을 정정하고 그 결과를 보관하는, 창호 교체 결정용 절차입니다. 이 절차가 일반 LLM보다 누락·오인식을 줄이는지는 같은 견적 사례로 대조해 보여드리겠습니다.”

**피해야 할 주장:** LLM은 PDF를 못 읽는다 / 출처를 못 찾는다 / 비교를 못 한다 / 우리 AI가 절감액을 계산한다 / 실견적에서 정확도가 입증됐다. 현재 어느 것도 근거가 없다.

**예선에서 그릴 한 화면:** 두 견적의 원문 인용·제품/단위/공사 범위·공개 성능 출처·‘확인됨/미확인/비교 보류’ 상태·업체 질문 버튼. ‘AI 답변’만 큰 화면에 배치하면 차별점이 사라진다.

**본선 검증 설계(미실행):** 합성 견적 6쌍에 같은 자료를 주고 ① 일반 LLM 프롬프트 ② 제안 서비스 ③ 단순 수기 표를 비교한다. 제품 오매칭, 누락 항목 미표시, 근거 없는 성능 수치, 비교 보류 실패를 사례별로 집계한다. 결과가 비슷하면 차별성을 입증했다고 말하지 않고 범위·주제를 다시 검토한다. 합성 자료의 성과를 실제 현장 성과로 일반화하지 않는다.

## I007 대안 질문 대응

“ChatGPT도 사진을 보고 빠진 항목을 말할 수 있습니다. 우리가 겨냥하는 차이는 사진 한 장의 설명이 아니라, **해당 작업이 덮이기 전까지** 공간·작업 단계별로 어떤 기록이 제출·미제출·검토 대기인지 추적하는 흐름입니다. 다만 기존 현장 기록 앱도 유사 기능을 제공하므로, 실제 팀의 반복 누락 사례와 추가 가치를 확인하기 전에는 신규성으로 단정하지 않겠습니다.”
