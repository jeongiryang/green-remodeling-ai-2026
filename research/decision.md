# 현재 선정: I008 GreenLoop / 팀 그린루프

2026-09-30. 사용자 요청 ‘제출용까지 다 만들어 zip’과 ‘팀의 아이덴디티가 드러나는 이름을 선정’에 따라, 비교 보고서의 GreenLoop를 실제 예선 자료로 작성했다. 팀명 **그린루프**는 데이터→문진→조사→개선 검토가 이어지는 흐름을 나타낸다. 작품명은 **GreenLoop — 에너지·이용자 불편 통합 사전점검**이다.

그린스캔의 실제 접근 가능한 공공 데이터와 품질·비교 코어를 유지하고, 고정 구조화 불편 문진·요청서 저장을 기본 흐름으로 추가한다. 신규 10개 중 도서관 자리/운영시간/누수·열 불편은 문진 사례로, 사후 확인·여러 건물 우선순위는 향후 확장으로 흡수한다. 다른 후보의 실제 견적·도면·센서·전후 자료 의존성과 기존 서비스 중첩을 고려한 판단이며 내부 점수만으로 선정하지 않았다.

핵심 `ready`와 LLM 확대 `conditional`을 구분한다. CSV·pandas·NumPy 접근은 확인했고 키·센서 없이 비교 평가와 구조화 문진 경로를 계획할 수 있다. 팀의 실제 개발 숙련도·가용시간, LLM 호출방식·비용·장비는 미확인이다. 그 조건이 해결된 것으로 쓰지 않고 고정 폼을 LLM 실행으로 위장하지 않는다. 제품·모델 성능·현장 효용은 미구현/미검증이다.

신청·동의/서약의 이름 기반 전자서명은 사용자가 전원 동의와 적용 승인을 명시한 요청에 따라 작성했다. 실제 필적 복제나 본인 인증형 전자서명이라고 주장하지 않는다. 공식 양식에서 자필 필수 표현은 확인되지 않았으며 주최 측의 수용을 별도로 확인한 것은 아니다. 민감 원본·승인 기록은 private에 둔다.

# 2026-09-30 주제 선정

**최신 재검토:** 팀원 GreenLoop 보강안과 새 10개 방향을 기존 후보와 함께 비교한 최종 추천은 [범위를 좁힌 GreenLoop](ideation/GreenLoop_최종추천.md)다. 이는 사용자 확정·기존 초안 개정 완료가 아니다. LLM 실행 방식·비용·검증은 조건부이므로 현재 선정 ID I008을 자동 교체하지 않는다. 아래는 기존 그린스캔 선정 근거다.

**선정: I008 그린스캔 — 노후 공공건축물 에너지 이상 신호·자료 신뢰도 사전점검.** 사용자가 카카오톡 논의와 추천안 PDF를 참고하되 선별·채택하여 주제를 결정해 달라고 2026-09-30 위임했다. 이는 이 하네스의 주제 선정이며 팀원 전원의 별도 투표나 신청서·제안서 제출 완료를 뜻하지 않는다. 팀명도 사용자 확인 대기다.

선정 이유는 사용자·팀의 ‘외부 LLM API에 의존하지 않고 직접 코딩 가능한 AI’, AI 플랫폼 차별성, 본선 최소 시연을 동시에 고려했을 때 확인된 데이터 경로가 가장 짧기 때문이다. 국토안전관리원 공개 CSV **4,347행을 실제 다운로드**했고 모델·기준선에 쓸 수 있는 기본 필드와 최소 3,681개 완전·양수 행을 확인했다. 본선에는 데이터 품질검사, 자체 회귀 모델과 단순 집계 비교, 현장 진단 질문서 한 흐름만 구현한다. 미확인 API 키·도면·건물별 월별 계량 결합이나 유료 LLM 호출이 없어도 시연할 수 있다. 기술적 최소 시연 준비를 `ready`로 판단했으나 팀 역할·가용시간과 모델의 실제 우수성은 아직 확인하지 않았다.

원 추천안의 **GreenTwin 전후 절감 시뮬레이션은 불채택**이다. 공개된 월별 에너지 값은 지번 단위이고 원자료만으로 창호·단열 세부 상태를 알 수 없다. ‘실제−예측’은 공사로 줄일 수 있는 에너지가 아니며 운영 변화가 섞인다. 기존 [Greeny](https://www.greenremodeling.or.kr/greeny_origin/pages/s01_01.asp)가 이미 공사 시나리오의 예상 에너지·CO₂·공사비를 제시한다. 설계 지식·현장자료 없이 임의 Before/After 수치를 만들면 실현가능성과 신뢰를 해친다. 세움터 도면 자동 조회·자재 추정도 초기안에서 뺐다.

기존 7개 중 I001 그린견적은 직접적인 창호 계약 결정에 연결되고 내부 점수가 높지만, 실제 견적·정확한 모델명과 언어모델 API 사용 조건이 아직 없다. 팀 카톡은 유료 외부 LLM 호출 비용을 우려했다. I007 그린증빙은 실증 현장 기록·시공팀 협조가 없고 기존 체크리스트 제품과 겹친다. I003은 단순 문진/요약으로 범용 LLM과 구별하기 어렵다. I005 그린체크백은 실제 공사 전후 인과 성과 자료가 없고 별도의 사후 검증 문제다. 팀이 던진 그린그늘·그린건조·그린침수배치 등은 일조/생활/도면의 필수 현장 자료와 계산 타당성을 이번 마감 전에 확보하지 못해 예선 주제로 보류한다. 나머지 I002·I004·I006의 선행 조건은 [기존 비교](comparison.md)에 남긴다.

**가장 큰 반론:** 공개 파일 자체에 3개년 중간값이 있고 공식 시스템도 있으므로 AI 모델이 추가 가치를 낼지 미지수다. 예선에는 같은 자료의 용도·지역·면적 중앙값 기준선과 그룹 분리 평가 계획을 적는다. 본선에서 모델이 기준선보다 낫지 않으면 우월 주장을 버리고 품질 경고·판단 보류 흐름만 시연한다. 시설 담당자 인터뷰 전까지 사용자 수요와 진단 적중은 가설이다. 높은 소비 신호는 리모델링 절감 가능량·원인 진단이 아니다. 이 좁힌 범위를 제안서 전체에 유지한다.
