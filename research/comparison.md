> 최신 선정(2026-09-30): **I008 GreenLoop**, 팀 **그린루프**. 기존 데이터 비교 코어에 구조화 불편 문진·현장 요청서를 추가하고, LLM 자유문 처리는 조건부 확대 계획으로 구분했다. 전체 신규 방향의 후순위 이유는 [최종 비교](ideation/GreenLoop_최종추천.md), 현재 범위는 [I008](ideation/I008.md), 결정은 [decision](decision.md)를 참고한다.

# AI 플랫폼 아이디어 7개 후보 심층 비교

**2026-09-30 최신 검토:** 기존 후보·그린스캔·팀원 GreenLoop 및 신규 10개 방향을 비교한 [최종 추천 보고서](ideation/GreenLoop_최종추천.md)를 추가했다. 추천은 에너지 사전점검·불편 문진·현장조사 요청서로 좁힌 GreenLoop이며 LLM 확대안은 조건부다. 현재 등록 선정 I008 및 그린스캔 초안은 유지한다. 아래 9/29 점수·추천은 과거 검토이며 최신 선정으로 읽지 않는다.

2026-09-29 갱신 · AI 플랫폼 아이디어 부문 · 사용자 선정 전

**범용 LLM 대비 재심사 후 현재 추천은 I001 ‘그린견적’, 조건부 대안은 I007 ‘그린증빙’이다.** I003 ‘그린문진’은 구현은 간단하지만 일반 LLM 대화와 차별화하기 어려워 대안 추천에서 내렸다. I006은 전문가 검수 규칙이 확보될 때만 재검토한다. 이 판단은 제품 성능 검증이 아니라 [7개 후보의 LLM 기준선·반박 답변 검토](llm-baseline.md)다. 9/28의 18개 방향·5개 심층 후보에 이어, 9/29 사용자 요청으로 I006·I007을 추가해 총 7개를 비교했다. 기존 5개 후보·점수는 유지했으며 아래 원래 순위와 내부 점수는 LLM 대비 재심사를 반영하지 않는다. [탐색·보류 및 확장 기록](ideation/screening.md)

9/28 후보 출처 18건에 이어 9/29 공식·1차 출처 6건을 추가해 전체 출처는 81건이다. 기존 제품·설명서·시계열 확인에 더해 DOE/PNNL 지침 HTML, EU의 단계적 개보수 전략 PDF와 CompanyCam 도움말을 실제 열었다. **한국 사용자 인터뷰, 실제 견적·인계·시공 기록, AI 성능 검증은 아직 없다.** 팀 숙련도에 대한 사용자 답변은 ‘잘 모르겠어’였다. 모든 후보는 조건부 구현 가능이며 제품 개발은 본선 진출 확인 후 진행한다.

인시는 **팀 전체 작업시간의 합**이다. 웹/Python 기초 담당자 1명과 API를 사용할 수 있고, 나머지 팀원이 자료 검수·화면·평가를 나누어 맡는다는 가정이다. 이 역할 배정은 아직 사용자 확정이 아니다. 새 기술 학습·현장 섭외·배포·상용 보안·운영 비용은 별도다. 현재 4인 팀 기준으로 4명×하루 2시간×6일은 48인시지만 팀원이 해당 시간을 낼 수 있다는 확인은 없다. 본선 진출 발표 이후 사전 준비가 어디까지 허용되는지도 후속 안내에 맞춘다.

## 2. 각 아이디어의 서비스 모습과 평가

### I001 그린견적 — 가장 추천

**한 문장:** “이 창호 견적 두 개, 같은 제품 성능과 공사 범위를 비교하고 있는지 먼저 확인해 준다.”

합성 시연 장면은 A안에는 철거·폐기가 포함되고 B안에는 제품 공급만 쓰인 상황이다. 사용자가 견적을 넣으면 AI가 모델·유리 구성·치수·수량·포함 항목을 추출하고 원문을 붙인다. 공식 성능 정보는 정확한 모델과 구성이 확인될 때만 연결한다. 이름이 비슷하거나 항목이 빠졌으면 ‘미확인/비교불가’와 업체에 보낼 질문을 보여준다. 최저가나 최적 공사를 자동 선정하지 않는다.

견적 비교에서 비용뿐 아니라 효율·모델·보증을 확인해야 한다는 업무 근거가 있다. [ENERGY STAR 계약업체 안내](https://www.energystar.gov/saveathome/heating-cooling/10-tips-hiring) 한국에너지공단의 [창세트 상세 예](https://eep.energy.or.kr/certification/certi_view_144.aspx?no=144251406)를 직접 열어 실제 연결할 필드를 확인했다. 단, 등록 제품 성능이 현장 시공 결과를 보증하지는 않는다.

기존 [SI-SO](https://www.si-so.co.kr/)도 AI 견적 분석을 제공한다고 소개한다. 따라서 **‘AI가 견적을 읽는다’ 자체는 새로움이 아니다.** 우리가 제안하는 차이는 창호 성능의 출처와 견적상 제품·범위를 연결하고, 부족한 정보 때문에 비교할 수 없는 이유를 드러내는 것이다. 이 차이가 고객에게 유용한지는 실견적으로 확인해야 한다.

본선에는 창호 1공종·견적 2개·텍스트 PDF·소수 제품 정보·질문표 저장만 구현하면 된다. 가장 설득력 있는 시연은 ‘저렴한 견적을 추천’하는 장면보다 **누락·불일치를 잡고 잘못된 성능 매칭을 거부**하는 장면이다. 6쌍 합성 견적과 일부 숨긴 평가 세트를 계획했다. 현재 실견적이 없으므로 정확도·업무시간 감소는 주장할 수 없다.

### I003 그린문진 — 기존 구현 부담 대안, LLM 재심사 후 후순위

**한 문장:** “춥다·덥다·답답하다는 거주자의 말을, 전문가가 확인할 공간별 요구서로 바꾼다.”

‘작은방은 밤에 춥고 거실은 오후에 덥다’고 적으면 두 공간의 상황을 나누고 빠진 조건만 질문한다. 답을 받으면 사실·추측·현장 확인 필요를 구분한 요구서를 만든다. 주관적 불편을 단열재 결함이나 특정 공사가 필요하다는 진단으로 바꾸지 않는다.

이용자 의견을 건물 개선에 활용하는 [CBE 설문 서비스](https://cbe.berkeley.edu/resources/occupant-survey/)가 선행한다. 우리 제안은 만족도 벤치마킹보다 공사 상담 전의 자연어 문진과 요청서 전달에 집중한다. CBE 문항은 복제하지 않으며 자체 질문을 만든다.

외부 센서·전문 학습 데이터 없이 텍스트·웹 화면으로 범위를 줄일 수 있어 구현 난도가 가장 낮다. 다만 고정 설문보다 질문 부담이나 누락이 줄지 않는다면 AI의 의미가 약하다. **같은 정보를 받는 고정 양식과 직접 비교**해야 한다. 상담 담당자가 요구서를 받아 실제로 쓸 의향이 있는지도 확인해야 한다.

### I002 그린인수인계 — 운영 현장에 접근할 수 있을 때 유리

**한 문장:** “리모델링으로 설치한 환기설비의 설명서와 운영 메모를, 다음 담당자가 이어받을 업무로 정리한다.”

모델·제어기·설치 구성을 확인한 뒤 담당자의 메모와 질문에 맞는 설명서 근거를 보여준다. 사용자 확인 항목과 전문 서비스 담당자에게 맡길 항목을 구분하고, 미해결 문의를 후임자 화면에 남긴다. 모드 제어나 에너지 최적화는 하지 않는다.

실제 확보한 [Daikin 설명서](https://www.daikin.eu/content/dam/document-library/operation-manuals/vent/heat-reclaim-ventilation/vam-fc9/VAM-FC9_4PEN586308-1_2019_06_operation%20manual_English.pdf)는 인계·운전 모드·전문 유지관리의 구분을 확인하는 자료다. **해외 특정 모델**이므로 국내 시설 적용을 입증하지 않는다. 국내 모델 설명서 확보 실패와 잘못된 장치 유형의 PDF를 구분한 기록도 남겼다.

최소 구현은 문서 1개와 업무 기록이어서 비교적 작다. 그러나 단순 ‘설명서에게 질문하기’ 수준이면 공모전 차별성이 약하다. 시설 담당자를 만나 인계 때 반복해서 빠지는 정보가 무엇인지 확인할 수 있을 때 추천 순위가 올라간다.

### I004 그린합의 — 문제는 좋지만 효용 입증이 어려움

**한 문장:** “효율 개선 공사를 두고 임대인·임차인이 서로 다르게 말하는 비용·일정 조건을 같은 표에서 확인한다.”

양측이 입력한 조건을 AI가 정리하고, 비용·일정 가능 여부는 규칙으로 계산한다. 둘의 비용 한도 합계가 공사비보다 작으면 부족분을 그대로 표시한다. 지원금이나 절감액을 임의로 넣어 합의 가능한 것처럼 만들지 않는다. 결과는 논의 자료이며 계약서나 공정성 판정이 아니다.

[IEA의 분리 유인 설명](https://www.iea.org/reports/asset-values)으로 구조적인 문제는 뒷받침된다. 기존 [그린리스 접근](https://www.energy.gov.au/publications/hvac-factsheet-green-leases)도 있으므로 ‘이해관계 조율’ 자체가 새로운 발상은 아니다. 자연어 조건에서 누락·충돌을 찾는 좁은 기능을 검증해야 한다.

화면 구현은 가능하지만 양측 참여·신뢰·실제 협상 결과를 확보하기 어렵다. 돈이 부족해서 못 하는 공사는 정보 정리만으로 해결되지 않는다. 마감과 구현 용이성 기준에서는 1~3순위보다 불리하다.

### I005 그린체크백 — 기술적으로 의미 있지만 이번에는 후순위

**한 문장:** “공사 후 줄어든 사용량을 날씨·휴관·이용 변화와 함께 설명하고, 아직 판단할 수 없는 부분을 알려준다.”

사용량·기상·운영 메모를 넣으면 데이터 품질과 비교 가능한 기간을 확인한다. 단순 기준선과 기온 모델을 비교하고 숫자와 근거를 설명한다. 데이터가 부족하면 추정치를 억지로 내지 않는다. [EVO](https://www.evo-world.org/en/807-main-menu/m-v)는 전후 조건 조정과 불확실성 공개를 강조한다.

[BDG2](https://github.com/buds-lab/building-data-genome-project-2)의 메타·기상 실파일과 전력 일부를 확인했다. 하지만 해외 2016~2017 데이터에 공사 정답이 없으므로 **이를 이용해 실제 리모델링 절감률을 입증할 수 없다.** [OpenDSM](https://github.com/opendsm/opendsm)도 이미 정규화 분석·자료 충분성 검사를 제공하고, 2024 수상작에 에너지 시그니처 분석이 있다.

계산·통계·데이터 해석의 부담이 7개 중 가장 크다. 실제 공사 데이터와 통계 담당자가 확보되기 전에는 이번 팀의 최우선안으로 권하지 않는다.

### I006 그린순서 — 한 번에 못 하는 공사를 나눠 준비

**한 문장:** “올해와 다음에 할 공사 사이에서 먼저 확인할 조건을 찾아준다.”

노후 단독주택 소유자가 공사를 나눠 하려 할 때, 희망 공사·시기·상담 메모를 넣으면 AI가 작업과 제약을 정리한다. 출처가 있는 소수 선행 조건과 대조해 단계별 검토안을 보여주고, 모르는 조건은 확인 질문으로 남긴다. 지붕 단열 계획에 미해결 누수 메모가 있다면 누수 상태 확인·보수 검토를 먼저 표시한다. 이 관계의 예는 [DOE 안내](https://www.energy.gov/cmei/scep/wap/whole-house-weatherization)에서 확인했다.

**최소 구현은 작업 4개·2단계·검토 규칙 3~5개**다. 자연어 추출·설명은 AI, 조건 검사·배치는 규칙으로 처리한다. 단가·절감률·최적 시공 순서를 AI가 생성하지 않는다. 사용자가 비용을 입력하지 않으면 예산 적합 판정도 보류한다.

단계별 개보수 로드맵 자체는 [EU 2020 전략의 선행 개념](https://energy.ec.europa.eu/system/files/2020-10/eu_renovation_wave_strategy_0.pdf)(PDF 9쪽)이다. 제안 차이는 소유자의 흩어진 상담 메모에서 **미확인 선행 조건**을 드러내는 흐름이다. 외국 지침을 한국 공법에 그대로 적용할 수 없어 검수자가 필요하다. 기존에 보류한 ‘전 공종 자동 설계’와 달리, 상담 준비용의 제한된 조건 검토로 축소한 후보다.

### I007 그린증빙 — 마감 전에 남겨야 할 기록 챙기기

**한 문장:** “단열·창호 공사 내용을 확인할 기록이 있는지, 가려지기 전에 확인한다.”

작업 설명을 입력하면 AI가 공간·단계별 기록 항목 초안을 만들고 담당자가 확인한다. 현장 사진의 설명과 메모를 해당 항목에 연결해 미기록·다른 공간·시점 미확인 항목을 보여준다. 단열 공사에서 마감 후 사진만 있다면 ‘시공 불량’이 아니라 **‘마감 전 확인 기록 없음’**으로 표시한다. 마감 전 검사의 중요성은 [PNNL 단열 검사 안내](https://basc.pnnl.gov/resource-guides/insulation-installation-achieves-resnet-grade-1)의 사례에서 확인했다.

최소 구현은 한 공종·방 1개·항목 8개 이내·사진/설명 연결·누락 보고서다. 사진 내용 자동 판독을 제외하면 대규모 이미지 학습 데이터 없이 시연할 수 있다. 사진 보유·파일 시각을 품질이나 진위의 증명으로 취급하지 않고 사람의 확인 상태를 따로 둔다.

[CompanyCam 공식 도움말](https://help.companycam.com/en/articles/6828391-creating-a-checklist)에 문서 변환·AI·사진 요구·조건부 체크리스트가 이미 있다. 단순 AI 체크리스트를 차별점으로 주장하기 어렵다. 그린 공종의 기록 시점과 근거 추적에 특화해 **실제 누락이 줄어드는지** 입증해야 한다. 현장 사진·시공팀 협조는 아직 확보하지 않았다.

## 3. 예선 배점에 맞춘 내부 비교

공식 배점인 문제 20·적합성 20·창의성 25·실현가능성 20·발전가능성 15를 적용했다. 각 항목은 0~5점 내부 판단이다. 환산은 `항목 점수 ÷ 5 × 배점`의 합이며 **예상 심사점수·합격 확률이 아니다.** 세부 이유는 각 후보 문서와 `candidates.json`에 기록했다.

| 후보 | 문제 | 적합성 | 창의성 | 실현가능성 | 발전가능성 | 환산 /100 |
|---|---:|---:|---:|---:|---:|---:|
| I001 그린견적 | 4 | 4.5 | 3.5 | 4 | 4.5 | 81 |
| I003 그린문진 | 3.5 | 4 | 3.5 | 4.5 | 4 | 77.5 |
| I006 그린순서 | 4 | 4.5 | 3.5 | 3.5 | 4 | 77.5 |
| I007 그린증빙 | 4 | 4.5 | 3 | 4 | 4 | 77 |
| I002 그린인수인계 | 3.5 | 4 | 3 | 4 | 4 | 73 |
| I004 그린합의 | 4 | 4 | 3.5 | 3 | 3.5 | 72 |
| I005 그린체크백 | 4.5 | 4.5 | 2 | 2.5 | 3.5 | 66.5 |

점수 차이는 불확실성보다 작을 수 있다. 예를 들어 I001의 실현가능성을 4→3으로 낮추면 총점은 77로 I003보다 낮아진다. **실제 모델명이 있는 견적을 다룰 수 있느냐**가 순위를 뒤집는 핵심 가정이다. 국내 사용자 인터뷰가 전무하므로 어느 후보도 수요 검증 완료로 볼 수 없다.

**9/28 당시 판단(9/29 LLM 재심사로 변경):** I001을 우선 검토하되 문서 추출·제품 일치 확인을 담당할 사람과 작업시간을 확보하기 어렵다면 I003으로 좁히는 안이었다. 현재는 I003의 범용 LLM 대비 차별성이 약해 I007을 조건부 대안으로 올렸다. I002는 실제 시설 담당자와 설치 모델 자료가 확인될 때만 재검토한다. I004와 I005는 당장의 제출안보다 보류 후보로 둔다.

최종 선정 전에 API 사용 가능 환경·기본 웹 작업 담당·가용시간·평가 정답 검수 담당을 확인해야 한다. 이는 사용자의 기술 숙련도를 재차 추궁하려는 것이 아니라 `ready`로 표시할 근거를 남기기 위한 내부 조건이다. 이번 조사에서는 제품 구현이나 외부 AI API 호출을 하지 않았다. 선정 이후 예선은 화면 구성안·흐름도와 검증 계획으로 설명하며, 본선 진출 후 실제 구현한다.

## 5. 예선 문서로 바로 연결할 제안 구조

선정 시 다음 내용을 바탕으로 15쪽 이내 제안서와 2쪽 이내 공식 요약서를 작성할 수 있다. **아래는 작성 순서 제안이며 실제 제출물은 아직 없다.**

1. 대상 건물·이용자와 결정이 막히는 한 장면.
2. 공식·1차 근거와 미검증 가설의 구분.
3. 기존 서비스와 제안 기능의 차이.
4. 입력→AI 처리→사용자 확인→다음 행동.
5. 핵심 비교 화면 또는 요구서 화면 1개.
6. 접근 가능한 데이터·미확보 자료·대안.
7. 규칙 처리와 AI 처리의 역할 분담, 틀릴 때의 동작.
8. 본선 최소 구현 범위·역할·시간 가정.
9. 비AI 기준선과 평가 세트·목표, 확장 가능성.
10. 출처 및 AI 도구 활용 기록.

효과는 우선 필드 정확도·사실 보존·잘못된 확정 방지·업무시간으로 검증한다. 에너지 절감률·탄소 저감량·공사 성사율은 현재 측정하지 않았으므로 수치 목표를 끼워 넣지 않는다.

## 2026-09-30 팀 제안 필터링과 최종 비교

팀 카카오톡의 GreenScan+GreenTwin 제안을 I008 그린스캔으로 좁혔다. 새로 확인한 국토안전관리원 CSV 4,347행 중 기본 품질조건을 통과한 3,681행을 본선 데이터 경로로 삼는다. 외부 AI API·건축HUB 키·대규모 지번 결합 없이 단일 웹 화면과 자체 회귀 모델을 시도할 수 있다. 실제 모델 성능은 미측정이다. 원안의 ‘예측 잔차 = 절감 여지’, 임의 전후 절감률, 도면/자재 자동 조회는 근거가 없어 제외했다. 기존 Greeny도 이미 전후 시뮬레이션을 제공한다.

| 후보 | 확인한 강점 | 오늘 결정에 중요한 약점 | 판단 |
|---|---|---|---|
| I008 그린스캔 | 공개 4,347행 실제 확보, API 키·유료 LLM 없이 시연 경로 | 공개 중앙값/Greeny와 차별성은 그룹 평가·업무 검증 전 가설 | **선정**, 좁은 사전점검 |
| I001 그린견적 | 창호 공사 결정과 직결, 공식 제품 정보 확인 | 실견적·모델명 부재, 외부 LLM API 의존 계획과 팀 비용 우려 | 보류 |
| I007 그린증빙 | 누락을 막는 업무 흐름 | 현장 기록·시공팀 미확보, 기존 체크리스트 제품 | 보류 |
| I005 그린체크백 | 데이터 기반 AI 분석 | 공사 전후 실제 자료 없어 인과효과 검증 불가 | 보류 |

I008의 내부 점수 79.5/100은 조사 비교 보조값이며 예상 심사점수나 AI 성능이 아니다. 최고점 자동 선정이 아니라 실제 데이터가 확보된 구현성과 팀의 외부 LLM 비용 우려를 우선했다. 세부 선택·반론·철회 조건은 [결정 기록](decision.md)과 [I008 심층 검토](ideation/I008.md)에 있다.

9/29 추가 비교: I006과 I003의 환산점수는 같지만, 현장 기술 검수 의존성이 더 작은 I003을 앞에 두었다. I006의 가장 강한 반론은 현장 조사 없이 순서를 확정할 수 없다는 점, I007은 기존 기록 도구로 충분할 수 있다는 점이다. 두 후보 모두 API·개발 담당·시간·검수 조건을 확인하기 전에는 `ready`로 바꾸지 않는다. 사용자 요청은 후보 수 확장이며 최종 주제 선정은 아니다.
