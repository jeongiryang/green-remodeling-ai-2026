# I001 그린견적 — 창호 견적의 성능 근거·공사 범위 비교

2026-09-28 · 후보 제안이며 사용자 선정 아님 · 구현 준비: **conditional** · 제품 구현·효과 측정 미실시

## 대상 건물

창호 교체를 검토하는 노후 다세대주택 한 동. 구조·전 공종 설계는 제외.

## 이용자

공사 계약 전 2~3개 업체 견적을 받은 비전문 건물 소유자.

## 문제

총액이 다른 견적에서 제품 성능 차이인지, 철거·폐기·마감 등의 포함 범위 차이인지 구분하기 어렵다.

## 확인한 근거와 아직 모르는 것

ENERGY STAR는 항목별 비용·효율·보증·모델 비교를 권고하고 SI-SO도 견적 해석 업무를 서비스화했다. 다만 국내 창호 소유자의 실제 이용 빈도·피해·지불의사는 인터뷰하지 않았다.

## 그린리모델링과의 연결

계약 전에 창호의 명시 성능과 누락된 공사 정보를 확인하게 하여 성능 개선 목적이 견적·제품 선택까지 이어지도록 돕는다. 실제 절감량은 산출하지 않는다.

## 구체적 사용 장면

합성 예시: A는 철거·폐기 포함, B는 창호 공급만 기재. 단순 총액 순위 대신 서로 같은 공사인지 먼저 확인한다.

## 입력

사용자가 제공하는 견적 PDF 또는 붙여넣은 텍스트, 업체·제품 모델·치수·수량·단위·포함 공사·보증. 공개 제품 정보는 별도 근거 레코드로 제공.

## 처리

문서 텍스트 추출→언어모델의 구조화 추출과 원문 위치 표시→사용자 정정→규칙으로 단위·모델 일치 검사→공식 성능 필드 연결. 모델 일부만 일치하면 자동 확정하지 않는다.

## 출력

견적별 공사 범위·명시/조회 성능·출처·누락 정보 비교표와 업체에 물어볼 질문. 알 수 없는 값은 빈칸이 아니라 미확인으로 표시.

## AI가 필요한 이유와 한계

비정형 견적의 동의어·문장·표를 같은 필드로 옮기는 부분에 AI가 유용할 수 있다. 가격 합산·단위 변환·공식 제품 검색은 규칙 처리하며 생성형 모델에 맡기지 않는다.

## 데이터 계획

한국에너지공단 창세트 상세 실제 열람. 실거래 견적은 미확보. 본선 최소 시연은 직접 작성한 합성 견적 6쌍과 공개 제품 1~3개 사실 필드로 구성하고 합성임을 표시.

## 실제 접근 상태

공단 제품 상세 HTTP 200에서 열관류율·유리·프레임·효율등급 확인. 기밀성·완료일자는 일부 비어 있음. API·대량 재사용 허가는 미확인이라 수동 확인한 소수 필드와 원문 링크로 시작.

## 기존 방식과의 차이

SI-SO의 가격·공종 분석과 겹치는 일반 OCR을 차별점으로 내세우지 않는다. 창호에 한정해 견적의 모델/구성과 공식 성능 정보의 연결 및 서로 다른 공사 범위의 미비교 이유를 보여준다.

## 비AI 비교 기준

동일 입력을 사람이 비교표에 옮기는 방식 및 단순 키워드 추출과 비교. 공단 검색 자체를 AI의 성과로 포장하지 않음.

## 검증 계획 — 아직 실행하지 않은 목표

합성 6쌍 중 3쌍은 개발용, 3쌍은 숨겨 둔 평가용. 팀 2인이 필드·누락 정답을 대조. 목표: 핵심 필드 정확도 90% 이상, 원문에 없는 수치 생성 0건, 3개 모델 불일치·단위 누락 사례 전부 경고. 목표이며 아직 실행하지 않음.

## 사용 흐름

견적 2개 입력→추출값 확인→동일 범위인지 대조→성능 근거와 미확인 항목 열기→확인 질문 저장.

## 예선에서 설명할 화면

A안/B안 두 열, 모델·유리 구성·열관류율·철거·폐기·마감·보증 행. 색으로 좋고 나쁨을 단정하지 않고 확인됨/미확인/비교불가를 표시하는 화면.

## 본선 최소 구현 범위

창호 1공종·텍스트 PDF·견적 2개·공식 제품 소수·질문 목록 저장까지. 범용 OCR, 전 공종 최적 설계, 최저가 추천, 실제 절감 예측은 제외.

## 도입 경로 가설

초기 사용자는 창호 교체 견적을 가진 소유자. 이후 상담기관·에너지 컨설턴트의 견적 확인 보조 도구 가능성은 가설이며 제휴는 없음.

## 실패 위험

잘못 추출한 모델·치수로 동등 제품처럼 보일 수 있다. 원문 인용·사용자 확인·정확 일치 조건으로 방지. 자료가 부실하면 비교불가가 많은데 이것이 사용 가치인지 확인이 필요.

## 가장 강한 반론

공식 모델명을 견적에 쓰지 않는다면 핵심 매칭이 자주 멈춘다. 일반 비교표보다 낫다는 증거가 없으면 창의성도 약하다.

## 추천이 바뀌는 조건

동의받은 견적 2쌍에서 확인 가능한 모델/구성이 거의 없거나 사용자가 비교표보다 업체 문의를 더 번거롭게 느끼면 I003을 우선 재검토.

## 선정 전 구현 준비 확인 조건

웹/Python 작업 담당·API 사용 방법·36~60인시 확보와 합성 견적의 필드 정답 검토 담당을 확인. 실제 수요 주장에는 별도 소유자/업계 인터뷰 필요.

## 본선 최소 시연 계획

**핵심 흐름:** 합성 견적 2개 업로드→필드 정정→차이/미확인/근거 확인→질문표 저장.

**데이터 성격:** 공식 창호 필드 실자료 + 합성 견적. 개인정보 없는 자료만 AI 입력. 실견적 확보 전 실제 고객 검증으로 부르지 않음.

**구성요소:** 단일 웹 화면, PDF 텍스트 추출, 외부 언어모델 구조화 출력, 단위·동일성 검사, 소규모 JSON 제품표, 결과 저장.

**미해결 의존성:** API 이용 가능 환경·요금·기본 웹/Python 담당자와 가용시간 미확인. 최소 제품 매칭·표 필드 검증을 수행할 담당자 필요.

**작업량 추정:** 내부 추정 36~60인시: 화면·입력 8~12, 추출·정정 10~18, 매칭·비교 8~14, 검증·시연 10~16. 기본 웹/Python 담당 1명과 API 사용이 가능하다는 조건. 학습·현장조사·상용 배포는 별도.

**실패 시 대안:** PDF 추출 실패 시 텍스트 직접 입력과 수동 정정. API 중단 시 사전 결과 재생을 명시하되 실시간 AI 검증 통과로 세지 않음.

**재현 가능한 완료 기준:** A안에 철거 포함·유리 사양 명시, B안에 철거 미기재·유사 모델 문자열을 넣으면 철거 미확인과 모델 확인 필요를 표시하고 성능 수치를 임의 매칭하지 않아야 함.
