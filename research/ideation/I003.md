# I003 그린문진 — 거주자 불편을 현장조사 요구서로 변환

2026-09-28 · 후보 제안이며 사용자 선정 아님 · 구현 준비: **conditional** · 제품 구현·효과 측정 미실시

## 대상 건물

단열·창호 개선 상담을 앞둔 노후 다세대주택의 개별 세대.

## 이용자

불편을 겪는 거주자, 내용을 받아 현장조사를 의뢰하는 소유자·상담 담당자.

## 문제

“집이 춥고 답답하다”는 설명만으로는 어느 공간·시간·조건에서 무엇을 확인해야 하는지 전달하기 어렵다는 가설.

## 확인한 근거와 아직 모르는 것

CBE는 이용자 피드백을 건물 운영·설계 개선에 활용하며 열쾌적·공기질 등을 구분한다. 이는 의견 수집의 활용 근거이지 한국 노후주택의 상담 오류 빈도나 우리 AI 수요 증거는 아니다.

## 그린리모델링과의 연결

거주 경험을 창호 주변·실별 열환경·환기 관련 현장 확인 요구로 정리하여 리모델링 상담의 입력을 개선. 단열 성능이나 곰팡이 원인을 온라인으로 확진하지 않는다.

## 구체적 사용 장면

합성 예시: “작은방은 밤에 춥고 거실은 오후에 덥다”를 두 공간의 사실로 분리하고, 창문·난방 상태 등 모르는 조건만 질문한다.

## 입력

거주자가 쓴 불편 문장, 방 이름, 시간·계절, 난방/창문 사용 조건, 선택적으로 동의받은 사진과 메모. 초기에는 텍스트만.

## 처리

자체 정의 필드에 추출→없는 필드에 한정해 후속 질문→답변 근거를 보존→사실/추측/현장확인 항목을 분리한 요구서 생성.

## 출력

공간·시간별 불편 카드, 아직 모르는 조건, 상담 시 확인할 질문을 담은 한 장짜리 요구서. 공사 품목이나 원인을 확정하지 않음.

## AI가 필요한 이유와 한계

자유서술의 맥락을 유지하고 이미 답한 질문을 반복하지 않는 적응형 문진에 활용. 고정 설문보다 정보 완성도·입력 부담이 나아지지 않으면 AI를 유지할 근거가 약함.

## 데이터 계획

CBE 공개 자료는 분류 개념·기존 서비스 비교에만 사용. 자체 작성 합성 거주 사례 12개와 자체 질문으로 시연. 실제 거주자 인터뷰·시공 전문가 검토·사진 데이터는 미확보.

## 실제 접근 상태

CBE 공개 소개와 측정 영역·FAQ를 읽음. 응답 원자료를 확보하지 않았고 CBE 문항/벤치마킹 지표 복제는 금지되어 자체 질문을 작성. 입력은 사용자가 직접 제공하며 주소·건강정보 수집은 최소화.

## 기존 방식과의 차이

CBE처럼 만족도 조사·벤치마크를 복제하지 않고 공사 전 거주자의 자연어를 현장 확인 요청서로 바꾸는 좁은 흐름. 국내 서비스 전체에서 최초라고 주장하지 않음.

## 비AI 비교 기준

동일 필드의 고정 설문과 사람이 대화를 읽어 요구서를 쓰는 방식. 질문 수·소요시간·사실 누락·불필요 질문을 비교.

## 검증 계획 — 아직 실행하지 않은 목표

12개 합성 사례 중 6개 개발·6개 평가. 목표: 필수 사실 보존 90% 이상, 입력에 없는 진단/원인 단정 0건, 모순·장소 미지정 사례 모두 확인 질문. 실제 사용자 최소 3명 탐색 인터뷰는 계획이며 아직 수행 안 됨.

## 사용 흐름

불편 설명→AI 후속 질문 2~4개→사용자 정정→실별 요구서 확인→상담용 저장.

## 예선에서 설명할 화면

왼쪽 거주자 대화, 오른쪽 방별 확인 사실·확인 필요 항목. 사용자 발언을 누르면 해당 근거가 보이는 1쪽 요구서.

## 본선 최소 구현 범위

텍스트 문진·실 3개 이내·요구서 생성·정정. 음성·열화상·도면 인식·실제 자동 진단은 제외.

## 도입 경로 가설

건물 소유자에게 주민 의견 취합 도구로 제공하거나 리모델링 상담 창구의 사전 접수에 활용하는 가설. 주민에게 직접 유료 판매할 근거는 없음.

## 실패 위험

잘못된 진단으로 공사를 유도할 위험, 고정 설문 대비 미미한 이점, 상담 담당자가 결과를 사용하지 않을 가능성. 출력은 검사 요청이며 기술 진단은 전문가에게 남김.

## 가장 강한 반론

고정 설문으로 충분하고 요구서를 읽을 상담 창구가 없으면 가치가 없다. 참여자 수가 적은 초기 테스트를 시장 검증으로 과장하지 않는다.

## 추천이 바뀌는 조건

소유자/상담 담당자가 이 요구서를 실제 현장조사 준비에 쓰겠다고 확인하고 I001 견적 자료 접근이 어렵다면 최우선 대안.

## 선정 전 구현 준비 확인 조건

API·웹 담당·24~40인시·자체 사례 정답 검토자를 확인. 효과 주장을 위해 고정 설문 비교와 상담 담당자 피드백은 별도로 필요.

## 본선 최소 시연 계획

**핵심 흐름:** 합성 거주자 불편 입력→누락 조건 질문→답변 확인→한 장 요구서 저장.

**데이터 성격:** 직접 작성한 합성 사례·자체 문항. 실제 사용자 자료는 동의 후 별도 검증하고 CBE 설문 복제 금지.

**구성요소:** 대화/정정 웹 화면, 구조화 언어모델 호출, 필수 필드 검사, 원문 근거 연결, 인쇄용 HTML.

**미해결 의존성:** API·기본 웹 담당·검증 담당자 미확인. 현장 진단까지 확장하면 전문가 필요하므로 최소 시연에서 제외.

**작업량 추정:** 내부 추정 24~40인시: 화면 6~10, 문진/추출 8~12, 요구서 4~6, 평가/오류 처리 6~12. 기본 웹/Python 담당과 API 전제. 새로 배우는 시간·실사용 인터뷰 제외.

**실패 시 대안:** 고정 설문과 수동 정정으로 요구서 생성. 이 경우 AI 기능 시연 성공으로 기록하지 않음.

**재현 가능한 완료 기준:** “작은방은 밤에만 춥다, 낮에는 비어 있다”를 입력하면 작은방·밤을 보존하고 조건을 묻되, 열관류율이나 단열재 결함을 만들어 내지 않아야 함.
