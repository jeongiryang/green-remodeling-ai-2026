# I004 그린합의 — 임대인·임차인의 공사 조건 비교

2026-09-28 · 후보 제안이며 사용자 선정 아님 · 구현 준비: **conditional** · 제품 구현·효과 측정 미실시

## 대상 건물

임대인과 임차인이 나뉜 노후 소규모 상가의 창호·설비 개선 논의.

## 이용자

공사비 부담·휴업 일정·임대 기간이 서로 다른 임대인과 임차인.

## 문제

공사비를 내는 사람과 사용요금 절감 편익을 받는 사람이 달라 개선 논의가 멈추는 구조적 문제.

## 확인한 근거와 아직 모르는 것

IEA가 임대인·임차인 사이의 분리된 투자 유인을 설명한다. 호주 정부는 그린리스라는 기존 접근을 소개. 한국 소규모 상가에서 서비스 사용·협상 개선이 발생할지는 미확인.

## 그린리모델링과의 연결

창호·설비 효율개선의 착수 조건과 분담안을 논의하도록 지원. 일반 임대차 상담·금융 상품으로 범위를 넓히지 않음.

## 구체적 사용 장면

합성 예시: 임대인은 공사비 한도, 임차인은 휴업 불가 요일을 제시. AI는 빠뜨린 조건을 드러내고 계산은 규칙 엔진이 수행한다.

## 입력

명시된 공사비, 각자의 일시 지출 한도·허용 휴업일·희망 공사시기·현재 임대 기간. 절감 예상치가 있으면 제공자·가정·범위를 함께 입력.

## 처리

발언→제약 필드 추출과 당사자 확인→규칙 기반 최대 3개 시나리오 계산→AI가 일치/불일치 조건을 근거로 설명. 공정성을 자동 판정하거나 계약서를 생성하지 않음.

## 출력

각자가 확인한 조건, 대안별 비용·일정, 미합의 사항, 다음 대화 질문. 합의된 사실은 당사자가 직접 확인한 것만 표시.

## AI가 필요한 이유와 한계

서로 다르게 쓴 제약과 숨은 불일치를 드러내는 역할. 입력이 모두 수치화되면 계산기·표만으로 충분하여 AI 필요성이 약해질 수 있음.

## 데이터 계획

공개 그린리스 개념 자료+팀이 직접 만든 8개 가상 조건쌍. 실제 임대차 계약·금융정보는 수집하지 않음. 국내 당사자 인터뷰는 미실시.

## 실제 접근 상태

IEA 및 호주 정부 소개 본문 열람. 이는 개념 근거이지 계약·시장 데이터가 아님. 당사자 조건은 직접 입력. 연결 PDF 다운로드 실패 기록을 보존했고 읽은 자료로 세지 않음.

## 기존 방식과의 차이

기존 그린리스의 원칙 소개보다 공사 논의 직전의 비정형 조건 정리와 충돌 표시로 축소. 법률 문서·금융 약정·임대료 조정 결정을 자동화하지 않음.

## 비AI 비교 기준

구조화된 조건 입력 양식+스프레드시트 3안 비교. AI가 추가로 발견한 모순과 잘못 요약한 조건을 평가.

## 검증 계획 — 아직 실행하지 않은 목표

합성 조건 8쌍을 개발 4·평가 4로 분리. 목표: 필수 제약 위반 대안을 가능으로 표시 0건, 비용 합계 계산 전부 일치, 없는 합의 생성 0건. 협상 성공률은 실제 당사자 실험 없이는 주장 불가.

## 사용 흐름

양측 조건 각각 입력→각자 추출값 확인→3안의 비용·일정 비교→미합의 항목 저장.

## 예선에서 설명할 화면

임대인/임차인 요구 두 열과 대안 3개, 비용 분담 합계·허용 일정·충돌 조건이 연결된 비교 화면.

## 본선 최소 구현 범위

공사 1건·당사자 2명·조건 최대 6개·대안 3개·대화 자료 저장. 계약 작성·지급·금융 연계 제외.

## 도입 경로 가설

상가 리모델링 상담기관의 중립적인 조건 확인 도구라는 가설. 당사자 모집·조정기관 파트너는 없음.

## 실패 위험

사용자가 AI 대안을 공정하거나 법적으로 유효한 결론으로 오인할 수 있음. 미합의 항목과 입력 가정을 보존. 이해관계자를 함께 확보하기 어렵고 MVP가 단순 계산기로 보일 수 있음.

## 가장 강한 반론

문제는 정보 정리보다 돈과 신뢰의 부족일 수 있다. 표를 잘 만든다고 공사가 성사되는지 불명확하다.

## 추천이 바뀌는 조건

실제 당사자 1쌍 이상에서 수기 협의의 반복 누락을 확인할 경우 재검토. 법률·금융 자동화 요구가 핵심이라면 현재 범위로는 보류.

## 선정 전 구현 준비 확인 조건

API·담당·32~56인시 및 가상 사례 제약 검수자 확인. 실제 효용 주장은 당사자 참여 검증 전 보류.

## 본선 최소 시연 계획

**핵심 흐름:** 가상 당사자 조건 입력→추출값 확인→규칙 계산→충돌 이유와 논의 질문.

**데이터 성격:** 가상 조건쌍만 사용. 절감액은 외부 입력이 있어도 추정으로 분리하며 현재 계산에 확정 편익으로 넣지 않음.

**구성요소:** 2인 조건 입력 화면, 구조화 추출, 제약 검사, 비용/일정 비교표, 결과 저장.

**미해결 의존성:** API·개발 담당·가용시간 미확인. 현장효과 검증에는 임대인·임차인 쌍의 참여 필요.

**작업량 추정:** 내부 추정 32~56인시: 입력 6~10, 추출/확인 8~14, 제약/비교 10~18, 평가 8~14. 기본 웹/Python 담당·API 전제, 다자 협상과 법률 검토 제외.

**실패 시 대안:** 구조화 양식과 수동 대안 입력. AI 없이 계산한 결과는 별도 표시. 조건 부족이면 가능 대안을 강제로 만들지 않음.

**재현 가능한 완료 기준:** 합성 공사비 1,000만원, 두 사람 한도 합계 800만원이면 200만원 미충족을 표시하고 지원금·대출·합의가 생겼다고 채우지 않아야 함.
