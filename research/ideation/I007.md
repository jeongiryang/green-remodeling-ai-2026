# I007 그린증빙 — 가려지기 전 시공 기록의 누락 확인

2026-09-29 · 사용자 요청으로 7개 후보에 추가 · 최종 선정 아님 · 조건부 구현 가능 · 제품 구현·효과 측정 미실시

## 대상 건물

단열 또는 창호 개선 공사를 진행하는 노후 소규모 건물. 시연은 한 공종·방 1개로 제한.

## 이용자

시공 기록을 전달하는 소규모 시공팀과 기록을 받아 전문가 확인을 의뢰하는 소유자.

## 문제

마감 후에는 내부 단열·접합부 상태를 기록할 기회가 지나갈 수 있고, 공사 약속과 사진·메모가 흩어져 무엇이 확인됐는지 정리하기 어렵다는 가설.

## 확인한 근거와 미검증 가설

PNNL은 단열 검사를 통상 마감 전에 수행하는 예를 설명하며 별도 시공 체크리스트도 제공한다. CompanyCam은 사진·문서 기반 기록 업무를 서비스화했다. 국내 누락률·분쟁 감소 효과는 미조사.

## 그린리모델링 연결

단열·창호 공사에서 성능과 관련된 작업 기록을 제때 모아 사람의 검토로 연결한다. 사진 보유만으로 단열 성능·기밀·시공 품질을 인증하지 않는다.

## 합성 사용 장면

합성 예시: 단열 공사 항목이 있는데 마감 후 사진만 제출됐다. “시공 불량”이 아니라 “마감 전 확인 기록 없음”을 보여준다.

## AI 역할

공사 설명과 기록 메모를 읽어 필요한 증빙 항목 초안을 만들고, 제공된 기록을 작업·공간·단계에 연결한다.

## 입력

사용자가 확인한 작업 범위와 전문가 검토용 체크 항목, 사진의 설명·공간·작성 시점·업로드 파일, 시공자 메모. 최초 MVP는 사진 내용 자동 판독을 제외.

## 처리

작업 문장→공간/단계/필요 기록 추출→담당자 확인→사진 설명·메모를 항목에 연결→규칙으로 누락·공간 불일치·시점 미확인 표시. 이미지의 실제 품질 판단은 하지 않음.

## 출력

작업 항목별 제출 기록·미기록·검토 대기 목록, 마감 전에 남겨야 할 미완료 기록과 확인 요청서. 기록 제출과 전문가 확인 완료를 서로 다른 상태로 관리.

## AI 필요성과 한계

현장별로 다른 작업 문구와 메모를 같은 기록 항목에 연결하는 데 AI를 활용. 파일 보관·날짜 비교·알림·해시 중복 검사는 일반 코드로 처리하며 AI로 포장하지 않는다.

## 데이터 계획

PNNL 벽 단열·창호 체크리스트 HTML 실제 확보. 작업/공간/단계/기록 유형이라는 자체 스키마를 설계할 근거로 활용. 현장 사진·국내 검수 기준은 미확보. 합성 작업 기록 10세트 및 샘플임을 표시한 첨부 파일로 최소 시연 계획.

## 실제 접근 상태

두 기술 체크리스트와 CompanyCam 도움말을 HTTP 200으로 받음. 현장 사진 데이터셋을 확보한 것이 아니며 타 기관 사진을 학습·데모에 복제하지 않음. 실제 사진에는 촬영·업로드 시각과 사용자 진술을 구별하고 메타데이터로 진위를 보장하지 않는다.

## 기존 방식·비AI 기준선

메신저 사진 폴더+스프레드시트 체크리스트와 비교. CompanyCam과 같은 범용 기록 도구의 기능 존재도 명시하며 성능을 직접 비교 시험한 것은 아님.

## 차별성과 중첩

CompanyCam은 이미 AI·문서 변환·사진 필수·조건부 체크리스트를 제공. 우리 제안은 단열/창호의 마감 전 기록 시점과 근거 추적에 초점을 둔 좁은 업무 구성. 기능 최초성보다 검토 누락 감소를 입증해야 함.

## 검증 계획 — 미실행 목표

합성 10세트 중 개발 5·평가 5. 목표: 작업/공간 연결 정확도 90% 이상, 고의로 누락한 기록 5건 모두 미완료, 다른 방·미확인 시점 기록을 자동 승인 0건, 첨부만으로 품질 인증 문구 생성 0건. 아직 실행하지 않음.

## 이용 흐름

작업 범위 입력→기록 항목 확인→단계별 사진/메모 첨부→누락·미확인 항목 확인→전문가 검토용 기록 묶음 저장.

## 예선 화면

왼쪽 공사 항목, 가운데 단계별 첨부 기록, 오른쪽 미기록/검토 대기 카드. 기록 제출과 현장 확인 완료를 다른 색·라벨로 표시.

## 본선 최소 범위

한 공종·방 1개·항목 최대 8개·파일/설명 연결·누락 목록·보고서 저장. 사진 하자 진단·3D·감리 대행·전자서명·외부 자동 알림 제외.

## 도입 경로 가설

소규모 시공팀의 기록 전달 보조·소유자의 전문가 검토 요청 도구라는 가설. 실제 시공팀 협조·유료 도입 의사는 없음.

## 위험

시공자가 기록하지 않으면 작동하지 않고 잘못된 사진 설명·시간 정보도 있을 수 있음. 기록 존재와 품질·진위는 별개. 범용 현장 기록 도구 대비 차이가 약하면 추가 기능에 그칠 수 있음.

## 가장 강한 반론

사진 찍는 일을 추가하면 현장에서 안 쓸 수 있고, 이미 있는 현장 기록 앱의 템플릿으로도 충분할 수 있다. 비전 AI 없이도 언어 추출이 유용한지 검증해야 함.

## 추천이 바뀌는 조건

실제 단열/창호 시공팀이 반복되는 기록 누락과 작은 웹 도구 사용 의사를 확인하면 우선순위 상승. 품질 자동 인증이 필수라면 이 후보의 범위를 벗어나 보류.

## 선정 전 준비 조건

API·개발 담당·32~52인시·작업 기록 정답 검수자 확인 필요. 실제 현장 적용 전 국내 체크 항목과 사진 수집 동의·협조를 확보해야 함.

## 본선 최소 시연 계획

**readiness:** conditional

**core_flow:** 합성 작업 문장→확인된 기록표→첨부/메모 연결→누락 목록→검토용 저장.

**data_mode:** 공개 참고 문서+합성 작업 기록+샘플 첨부. 실제 공사 품질이나 누락률을 검증했다고 주장하지 않음.

**components:** 웹 입력/첨부 화면, 구조화 언어모델, 작은 기록 스키마, 파일 메타·중복 규칙, 인쇄용 보고서.

**dependencies:** API·개발 담당·시간 미확인. 실제 운영에는 현장 담당자의 기록 협조·체크 항목 검수 필요. 국내 공법 적용은 전문가 확인 전 보류.

**effort_estimate:** 32~52인시 추정: 입력/첨부 8~14, 항목 추출/연결 8~12, 누락 검사/보고서 8~14, 평가/시연 8~12. 기본 웹/Python·API 가정, 이미지 판독·섭외·학습·상용화 별도.

**fallback:** 수동 체크 항목과 사용자가 직접 연결한 파일로 기록표 생성. AI 중단 시 수동 처리라고 표시. 이미 마감한 뒤 기록이 없으면 소급 사진 생성 대신 기록 없음으로 남김.

**acceptance_test:** 작은방 마감 전 기록이 필요한 합성 작업에 거실 사진 설명과 마감 후 메모만 넣으면 작은방 기록 미확인으로 남기고, 품질 합격·작업 완료를 자동 확정하지 않아야 함.
