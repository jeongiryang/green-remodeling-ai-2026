# I002 그린인수인계 — 리모델링 후 환기설비 운영 전달

2026-09-28 · 후보 제안이며 사용자 선정 아님 · 구현 준비: **conditional** · 제품 구현·효과 측정 미실시

## 대상 건물

열회수 환기설비를 새로 도입한 소규모 공공 커뮤니티시설. 특정 제조사 1개 모델로 최소 범위 제한.

## 이용자

상주 설비 전문가가 없는 시설의 운영 담당자와 후임 담당자.

## 문제

새 장비의 모델·제어 방식·설명서와 이전 담당자의 업무 기록이 분리되어, 후임자가 어떤 동작을 확인하고 누구에게 문의할지 파악하기 어렵다는 가설.

## 확인한 근거와 아직 모르는 것

Daikin 설명서는 사용자 변경 때 설명서를 인계하도록 하고 연결 방식별 조작 차이·전문 유지관리 범위를 명시한다. 해당 업무 필요성은 확인했지만 국내 시설에서 인수인계 실패가 얼마나 발생하는지는 미조사.

## 그린리모델링과의 연결

리모델링으로 설치한 열회수 환기설비의 운영·사후관리 인계에 연결. 장비 자동 제어나 에너지 절감 성과 보장은 하지 않음.

## 구체적 사용 장면

합성 예시: 후임자가 “열회수와 바이패스가 뭐가 다른지, 내가 필터를 분해해도 되는지” 물으면 모델별 원문과 담당 범위를 연결한다.

## 입력

장비 모델·설명서 PDF·제어기 종류·설치 방식 확인값·담당자가 작성한 업무 메모와 완료 여부.

## 처리

모델/설명서 버전 확인→관련 절 검색→인용 있는 업무 카드 생성→사용자 가능 업무/서비스 담당자 업무 분리→모르는 구성은 질문으로 반환.

## 출력

모드 의미·관련 설명서 쪽·담당자 확인 항목·미완료 문의·인계 기록. 근거 없는 운전 시간이나 필터 교체 주기를 생성하지 않음.

## AI가 필요한 이유와 한계

분산된 자연어 메모를 설명서의 정확한 항목과 연결하는 데 AI를 사용. 단순 예약·완료 체크는 일반 소프트웨어 기능이고 기존 매뉴얼 검색보다 빠른지 검증해야 함.

## 데이터 계획

Daikin VAM150FC/250FC 영문 12쪽 원문 실제 확보. 국내 시설에 설치된 모델 자료는 미확보. 한국어 설명은 번역의 검증이 필요. 시설 메모는 합성 12건으로 시작.

## 실제 접근 상태

제조사 PDF 로그인 없이 HTTP 200. 본문 1~5쪽에서 인계·모드·제어·전문가 유지관리 구분을 확인. LG 욕실 배기팬 PDF도 받았으나 열회수 모델과 다르므로 올바른 자료로 대체하지 않고 오매칭 검증 사례로만 사용.

## 기존 방식과의 차이

제조사의 모드 자동 선택이나 앱 제어를 다시 만들지 않는다. 여러 담당자가 무엇을 확인했는지와 미해결 문의가 다음 사람에게 전달되는 흐름이 제안 차이. 일반 문서 챗봇 수준이면 차별성 부족.

## 비AI 비교 기준

제조사 PDF 검색 + 기존 인수인계 체크리스트. 같은 질문을 찾아 답하는 시간과 누락 항목으로 비교.

## 검증 계획 — 아직 실행하지 않은 목표

개발용 질문 10개와 별도 평가 10개. 목표: 인용 근거 일치 90% 이상, 잘못된 모델·문서에 없는 질문 4개 전부 재질문/답변보류, 전문가 작업을 비전문 담당자에게 지시 0건. 아직 시험하지 않음.

## 사용 흐름

모델·설명서 등록→담당자 메모 입력→근거 있는 카드 확인→완료/문의 기록→후임자 화면에서 미확인 항목 이어받기.

## 예선에서 설명할 화면

시설 장비 1개 카드와 오늘 인계할 3개 항목, 원문 쪽 열기, 완료 확인·전문가 문의 버튼이 있는 화면.

## 본선 최소 구현 범위

한 모델의 설명서 검색·메모 변환·인계 기록. 센서·원격제어·자동 에너지 최적화·음성 인터페이스 제외.

## 도입 경로 가설

시설의 준공 인수인계 패키지 또는 유지관리 업체 업무 보조 가능성. 도입처·유료 수요는 미확인.

## 실패 위험

번역·모델 오매칭, 위험한 유지관리 지시, 일반 RAG와 약한 차별성. 모델/연결 구성이 확인되지 않으면 조작 안내 보류. 실제 시설 자료 없이 국내 현장 적합성을 주장하지 않음.

## 가장 강한 반론

PDF를 잘 정리한 설명서와 체크리스트면 충분하지 않은가? 인계 누락을 줄이는 효과 없이 챗봇만 붙이면 약하다.

## 추천이 바뀌는 조건

국내 해당 시설 담당자에게 실제 인계 누락 사례와 사용 의사가 확인되면 우선순위 상승. 국내 원문·검수자가 없으면 해외 예제 이상의 주장을 하지 않는다.

## 선정 전 구현 준비 확인 조건

API·담당·30~50인시와 정확한 한 모델 설명서의 검수자를 확인. 실제 국내 운영 안내에는 설치 모델/구성 일치 확인이 추가로 필요.

## 본선 최소 시연 계획

**핵심 흐름:** 한 모델 설명서와 인계 메모 입력→관련 근거 카드→담당자 확인→후임자 인계 기록.

**데이터 성격:** 해외 제조사 원문 + 합성 인계 메모. 국내 모델 도입 전 실제 모델에 맞는 설명서 추가 필요.

**구성요소:** 단일 웹 화면, PDF 쪽 단위 검색, 언어모델, 인용 검사, 업무 기록 JSON 저장.

**미해결 의존성:** API·팀 역량 미확인. 영어 설명 검수 가능자 또는 국내 동등 모델 원문, 실제 시설 담당자 검증 미확보.

**작업량 추정:** 내부 추정 30~50인시: 입력/화면 6~10, 검색·근거 카드 10~16, 인계 기록 4~8, 오류·번역 검증 10~16. 기본 웹/Python 담당·API 전제, 모델별 확장과 현장 실험 제외.

**실패 시 대안:** PDF 목차·해당 쪽 링크와 수동 체크리스트. 근거 없는 질문에는 답변 보류. 사전 생성 카드 재생은 녹화/고정 결과로 표시.

**재현 가능한 완료 기준:** 열회수 장비 대신 욕실 배기팬 설명서를 넣으면 모델 불일치로 멈추고, 유지관리 요청은 설명서상 자격 있는 서비스 담당자 업무라는 근거를 연결해야 함.
