# I005 그린체크백 — 리모델링 후 사용량 변화 설명

2026-09-28 · 후보 제안이며 사용자 선정 아님 · 구현 준비: **conditional** · 제품 구현·효과 측정 미실시

## 대상 건물

리모델링 전후 계량 자료를 보유한 소규모 커뮤니티시설.

## 이용자

공사 후 에너지 요금·사용량 변화를 설명해야 하는 시설 소유자·관리 담당자.

## 문제

청구액이나 전후 사용량 차이만 보고 날씨·운영시간·이용인원 변화와 공사 효과를 혼동할 수 있다.

## 확인한 근거와 아직 모르는 것

EVO는 전후 사용량을 조건 변화에 맞게 조정해 절감량을 산정한다고 설명한다. 통계적 방법은 기존 분야이며 단순 전후 차이가 공사 인과효과라고 주장할 수 없음.

## 그린리모델링과의 연결

그린리모델링 후 사용량 변화의 해석·데이터 보완·전문 성과검토 의뢰에 연결. 공인 성과인증이나 확정 절감량을 제공하지 않음.

## 구체적 사용 장면

합성 설명: 공사 후 사용량 감소와 동시에 휴관일이 늘었다면 감소량 전체를 공사 절감으로 표시하지 않고 조건 변화와 판정 한계를 보여준다.

## 입력

시간별 또는 일별 사용량 kWh, 기온 °C, 계량 기간·공사 시점·운영일·이용량 변경 메모. 청구금액만으로 사용량을 역산하지 않음.

## 처리

단위·결측·기간 검사→단순 계절 기준선과 기온 회귀 비교→시간순 평가→운영 변경 플래그→검증된 계산값만 언어모델이 설명. 표본 부족/분포 변화 시 성과 판정 보류.

## 출력

관측 사용량, 조건 보정 모델의 예상 사용량, 추정 범위·데이터 경고·추가 확인 질문. 일반 예측 오차를 리모델링 절감으로 명명하지 않음.

## AI가 필요한 이유와 한계

기온과 사용량 관계 학습은 통계/머신러닝 영역이며 생성형 AI는 운영 메모 분류·근거 설명에 제한. 기존 OpenDSM보다 계산이 혁신적이라고 주장하지 않음.

## 데이터 계획

BDG2 메타데이터·기상 전체와 전력 앞 24시간 접근·구조 확인. 전체 전력 평가 데이터·국내 공사 전후 실자료는 아직 준비 안 됨. 합성 공사 이벤트는 별도 표시하고 실제 데이터에 가짜 공사 날짜를 넣지 않음.

## 실제 접근 상태

원본 raw URL은 Git LFS 포인터였으며 media URL로 실제 메타/기상 데이터를 받음. 해외 2016~2017 자료. 전력은 24행 부분 수집으로 연간 모델 학습 검증 전. LICENSE의 ShareAlike 표시와 외부 소개의 차이가 있어 원자료 미재배포.

## 기존 방식과의 차이

2024 에너지 시그니처 수상안, OpenDSM의 정규화·충분성 검사와 많이 겹친다. 소규모 담당자가 데이터 부족과 운영 변화부터 이해하는 설명 흐름으로 차별화 제안하나 5개 중 독창성 가장 약함.

## 비AI 비교 기준

전년 동월/요일 사용량 및 단순 기온 회귀. 복잡한 모델이 시간순 보류 구간의 예측 오차를 줄이지 못하면 단순 모델 유지.

## 검증 계획 — 아직 실행하지 않은 목표

계획: 3개 건물에 대해 개발 기간과 이후 90일을 시간순 분리, MAE 및 결측 경고 평가. 목표는 기준선 대비 개선 여부 보고이지 임의 정확도 보장 아님. 공사 정답이 없는 BDG2에서 인과 절감률은 평가하지 않음. 계산값과 설명 숫자 불일치 0건 목표.

## 사용 흐름

사용량 CSV·기상·운영 메모 입력→품질 검사→비교 가능/불가 판단→변화 설명과 보완 목록 확인.

## 예선에서 설명할 화면

관측/모델 예상 사용량 그래프와 공사·휴업·이용인원 변경 타임라인, “현재 자료로 공사 효과 판정 불가” 카드.

## 본선 최소 구현 범위

시설 1개·전력 1종·일별 분석·기온 변수·설명 카드. 다에너지원 합산·CO2 인증·실시간 제어·요금 연동 제외.

## 도입 경로 가설

시설 소유자의 정기 성과 설명 보조. 공인 M&V·성과보증 계약·탄소크레딧 발급 기능으로 판매하지 않음.

## 실패 위험

시계열 누수, 결측/0 처리 오류, 날씨와 사용패턴의 분포 변화, 인과효과 오인, 라이선스·지역 대표성 한계. 통계 담당과 실제 전후 데이터 없으면 제출 핵심으로 삼기 어려움.

## 가장 강한 반론

이미 잘 정립된 분석 방법 위에 설명 챗봇을 붙인 것에 불과할 수 있다. 본선에서 모델 적합성과 효과를 설명할 통계 역량도 필요하다.

## 추천이 바뀌는 조건

실제 국내 공사 전후 데이터와 통계 담당이 확보되면 상승할 수 있으나, 선행작 대비 사용자 검증이 없으면 여전히 후순위.

## 선정 전 구현 준비 확인 조건

API·통계 담당·60~96인시·전체 시계열/이용조건 확인. 실제 절감 주장에는 공사 이력과 운영 조건의 별도 실증이 필요.

## 본선 최소 시연 계획

**핵심 흐름:** CSV와 운영 메모→단위/결측 경고→단순 조건 보정 그래프→근거 설명·판정 보류.

**데이터 성격:** 해외 공개 시계열로 처리 가능성 검증, 합성 이벤트는 별도 데모. 국내 실제 성과 검증 자료 없음.

**구성요소:** CSV 업로드, 시계열 정제·회귀, 시간순 평가, 그래프, 결과 숫자 기반 언어모델 설명.

**미해결 의존성:** API·통계/Python 담당·60~96인시 미확인. 전체 계량 시계열 선택·단위/기간 검증 및 원자료 이용조건 재확인 필요.

**작업량 추정:** 내부 추정 60~96인시: 데이터/품질 16~24, 모델/평가 20~32, 화면/설명 12~20, 오류/시연 12~20. 통계·Python 기본 지식 전제이며 미숙련 학습시간·현장 데이터 확보 제외.

**실패 시 대안:** 관측량·기온·결측 시각화와 판단 보류만 제공. 데이터 없는 상태에서 절감 추정 결과를 만들어내지 않음.

**재현 가능한 완료 기준:** 요금 원 단위만 있는 입력, 기준기간 부족, 운영일 급변 사례에서 확정 절감률을 출력하지 않고 각 이유와 필요한 자료를 표시해야 함.
