# I008 그린스캔 — 노후 공공건축물 에너지 이상 신호·자료 신뢰도 사전점검

2026-09-30 선정안. **본선 최소 시연 준비 가능(ready)**은 구현 완료나 성능 입증이 아니다. 예선에는 화면·흐름과 평가 계획을 제출하고 제품 구현은 진출 확인 후 진행한다.

## 한 문장 제안

연면적 3,000㎡ 이상 노후 공공건축물의 공개 에너지 소비량을 같은 용도·지역·규모의 건물과 비교해, **현장 진단을 먼저 검토할 신호**와 **판단을 보류할 자료 문제**를 함께 보여주는 AI 사전점검 플랫폼.

이용자는 여러 시설을 관리하는 지자체·공공기관 담당자다. 건물을 선택하면 관측 3개년 평균 1차 에너지 소비 원단위(kWh/㎡·년), 유사 조건 참고 범위, 보고 누락 여부와 함께 운영시간·이용인원·계량 범위·창호/단열/설비 상태를 확인할 질문서를 받는다. 신호는 **현장 확인 우선순위 제안**이며 공사 필요 판정이나 절감 가능량이 아니다.

## 채택한 근거

- [국토안전관리원 공개 CSV](https://www.data.go.kr/data/3069931/fileData.do)를 로그인 없이 직접 내려받았다. 4,347행·15열이며 지역·용도·연면적·사용승인일·보고 누락 수·3개년 소비 원단위가 같은 파일에 있다. SHA-256 `1a049b33df564410508ebbf1164d401d660eae75fcaa8f2de3c27367ac9c883a`; 로컬 사본은 Git 제외 `private/research/public-building-energy.csv`에 있다. 미보고 분기 0, 양의 원단위, 유효 면적·연도 조건을 만족하는 3,681행을 확인했다. 학습/검증에 쓸 최종 행은 추가 품질검사에 따라 더 줄 수 있다.
- 건축HUB 월별 전기·가스 [API](https://www.data.go.kr/data/15135963/openapi.do)는 지번 단위이며 신청 키가 필요하다. 건축물대장과 1:1 결합한 결과나 실제 호출은 아직 없다. 따라서 초기 필수 경로에서 제외한다.
- 기존 [Greeny 분석시스템](https://www.greenremodeling.or.kr/greeny_origin/pages/s01_01.asp)은 이미 노후도평가·시나리오별 에너지/CO₂/공사비 예상 효과를 안내한다. 전후 그래프 자체를 새로움으로 내세우지 않는다.
- [우선순위 문제를 다룬 창조센터 게시 글](https://www.greenremodeling.or.kr/n1/report2/view.asp?seq_=2970)은 담당자 업무 맥락 참고 자료다. 실제 담당자 인터뷰·도입 의향 검증은 아직 없다.

## AI와 일반 프로그램의 역할

**AI 입력:** 지역, 용도, 연면적, 사용승인연도, 층수와 실제 3개년 소비 원단위. 주소·기관명 및 공개 파일의 ‘3개년 중간값’은 학습 특성에서 제외한다. 중간값은 목표와 가까운 파생값일 수 있어 누출 위험이 있다.

**처리:** 결측·0·극단값 확인, 집계 기준선 작성, 회귀 모델 학습, 같은 주소/기관이 양쪽에 들어가지 않도록 그룹 분리 평가, 범위/불확실성 표시. **출력:** 참고 분포와 벗어남 신호, 보류 이유, 현장 확인 질문. 누락 분기나 비교군 부족 시 절감/고사용 판정을 내지 않는다.

AI가 필요한 이유는 용도·규모·지역·연도 관계를 데이터에서 학습해 단순 중앙값보다 선별에 도움이 될 **가능성**이다. 본선에서 그룹 분리된 미사용 데이터로 MAE와 범위 커버리지를 측정한다. 모델이 단순 중앙값보다 낫지 않으면 그 결과를 보고하고 AI 우월 주장을 철회한다. 범용 LLM에 같은 CSV를 주고 반복 실행·근거·보류 규칙을 비교할 계획이지만 아직 비교 실험을 하지 않았다. 화면·필터·질문 저장은 일반 소프트웨어 기능이고 유료 LLM API는 필수가 아니다.

## 잘라낸 원안과 반론

팀이 공유한 GreenScan+GreenTwin PDF의 ‘실제 사용량 − 예측값 = 개선 여지’는 채택하지 않는다. 차이는 운영시간·이용인원·계량 범위 등으로도 생기므로 리모델링 효과가 아니다. 임의로 ‘전 120 → 후 78 MWh, 35% 절감’ 같은 그래프를 실제 전망처럼 제시하지 않는다. 도면·자재·창호 세부 성능은 공개 에너지 API로 알 수 없고, 원안의 건물 주소 자동 조회도 초기 범위에서 제외한다.

가장 강한 반론은 **공개 데이터에 이미 중간값이 있고 Greeny도 의사결정을 돕는데 왜 모델이 필요한가**이다. 답은 성능을 단정하는 것이 아니라, 동일 자료의 단순 집계 기준선과 그룹 분리 평가를 공개하고 자료 신뢰도에 따라 판정을 보류하는 업무 흐름을 검증하는 것이다. 이 검증에서 이득이 없으면 차별점이 성립하지 않는다. 시설 담당자 인터뷰가 없으므로 실제 현장 유용성도 가설이다.

## 예선 화면과 본선 최소 구현

예선 화면 1장: 왼쪽 건물 선택/기본정보, 가운데 관측 원단위 점과 유사 조건 참고 범위, 오른쪽 ‘현장 확인 필요’ 또는 ‘자료 부족으로 보류’와 질문서. 단위, 데이터 기간, 출처와 원인 미확정을 명확히 표시한다. 공사 후 예측/탄소 절감 그래프는 넣지 않는다.

본선 최소 흐름: 공개 CSV 정적 로드 → 건물 1~3개 선택 → 품질검사 → 집계 기준선과 자체 회귀 모델 비교 → 신호/보류 사유 → 질문서 저장. 로컬 CSV로 오프라인 시연 가능하다. Python 데이터·모델 평가 14~22인시, 웹 화면 8~12, 보류·설명·검증 6~10으로 **총 28~44인시 내부 추정**이다. 4인 팀의 코딩 분담·가용시간은 아직 확정되지 않았다.

완료 테스트: 유효 행 1개에 관측값/참고 범위/출처를 보이고 이를 절감량이라 쓰지 않는다. 보고 누락 또는 0 원단위 행은 고사용 판정을 보류한다. 그룹 분리 평가에서 모델 성능이 기준선보다 나쁘면 AI 신호를 채택하지 않는다. 예선 시점에는 학습된 모델·성능 수치를 주장하지 않는다.

## 남은 위험

이 공개 자료는 3,000㎡ 이상 공공건축물 중심이며 소형·민간 건물에 일반화할 수 없다. 에너지 원단위가 높아도 창호·단열 문제가 원인이라고 단정할 수 없다. 진단 결과 정답이나 그린리모델링 전후 실측이 없어 실제 절감·현장 적중률은 평가할 수 없다. 이 위험을 해결하려면 시설 담당자 인터뷰, 실제 현장 진단 결과, 운영시간/점유 정보가 추가로 필요하다.
